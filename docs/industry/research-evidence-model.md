# 产业研究信号：证据、口径与使用方法

本页说明“投资结论”中的研究信号如何生成。它用于跟踪 AI 产业链的公开证据，不能替代个股估值、持仓管理或交易执行。

## 两层结果

### 正式评分

正式评分只使用满足全部条件的直接、可追溯指标：来源已接通、观测未过期、可计算同比或相应变化、目标环节的必需维度齐备，并达到所需的需求主体覆盖数。用于正式评分的指标还需要连续可比历史；短历史、项目样本、估计值、指引、第三方数据和广义代理均不能补齐正式门槛。

正式评分显示为“积极配置”“分批关注”“中性持有”“谨慎观望”或“降低暴露”时，页面会同时列出参与该结果的直接指标、报告期、版本和来源链接。它表达的是产业环节的研究倾向，不是股票的买卖指令、目标价或收益率预测。

### 先行研究信号

当正式评分的直接证据或连续历史仍不足时，页面可以显示“先行研究信号”。它使用两类明确标记的数据：

- 已接入但历史期数不足的直接公开数据；
- 范围较广的公开代理，例如建设支出、制造业订单、区域终端用电等。

先行信号有独立的覆盖数、需求主体数、历史质量和证据边界。代理只用于提前观察可能的变化方向，不能自动升级为正式评分，也不能代替项目级投运容量、AI 专属订单或企业合同数据。

## 五类因子

研究模型固定观察需求、盈利兑现、资本开支、建设进度和成本约束。每类因子先按公司或指标族合并，避免同一事实被多个指标重复放大。宏观利率、金融条件和通胀最多只调整风险环境，不替代产业基本面证据。

建设进度尤其需要区分三件事：公开项目公告、在建项目状态、已投运能力。项目公告的容量口径可能是计算能力、项目披露容量、发电能力或其他定义；不同口径不会相加成单一行业 MW，也不会因为未披露容量而填零。

## 数据状态

每条序列都会保留观察日期、来源发布日期（可获得时）、获取时间、版本哈希和来源链接。页面用下列状态说明数据边界：

| 状态 | 含义 |
| --- | --- |
| 已获取 | 本次成功读取到可用官方观测。 |
| 缓存 | 本次来源未能读取，保留最后一次成功观测并标记检查时间。 |
| 获取失败 | 来源本次未读取且没有可展示的成功版本。 |
| 尚未发布 | 指标已定义但官方新一期尚未发布。 |
| 未配置 | 指标需要新的公开来源、授权或解析配置。 |

缺失数据始终保留为空，既不填零，也不把月度数据插值为日度行情。缓存不会改变原始观测期，因此不会把旧数据伪装成新数据。

## 刷新机制

网页只读取已完成的后台快照。计划任务和 GitHub Actions 在后台检查来源、保留可追溯缓存、重算指标与研究结果；失败后按发布节奏重试。后台进程使用隐藏窗口方式运行，不会在桌面弹出命令窗口。

## 实际使用顺序

2026-09-30新增数据验证：26项序列每项抽查首期、中期、末期，共78个历史点通过官方原始缓存回读。记录保存在 `additional-evidence-verification.json`，包含数值、观测版本、单位及源链接；该核验不把广义代理升级为AI直接数据。

1. 先查看正式评分是否通过直接证据门槛；未通过时阅读先行信号和缺口，而不是把它当成确定结论。
2. 检查需求主体覆盖数及最新报告期，确认信号不是由单一公司或旧数据主导。
3. 打开证据标签，核对每条指标的来源、口径、日期和是否为代理。
4. 再结合公司估值、盈利预测、订单、资本开支、竞争格局和风险承受能力做独立判断。
