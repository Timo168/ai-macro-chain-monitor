# 公司财报自动更新

第一项优化：从官方发布列表发现实际报告链接，交给对应解析器核验财年、季度、实际期末、原币种和单位，随后构建行业图表与研究结论。前端新增「公司财报更新进度」，分别呈现发布、解析、来源检查和图表覆盖情况。

## 后台运行

- GitHub Actions 约每 15 分钟唤起已有调度器；财报官方列表每小时检查，完整财务历史每日检查。
- 新报告第一次发现后立即安排采集；已发布待采集报告按 30、60、120 分钟退避重试。新财报使用独立重试计数。
- 微软、Alphabet、Amazon、Meta、NVIDIA、Dell 和 AMD 支持按公司定向重抓最新季度，避免反复获取全部历史。
- 页面关闭后任务继续运行；页面「检查产业数据」重读后台最新缓存。任务时刻受 GitHub 调度和上游发布时间影响，不承诺在公告瞬间更新。
- Windows 请求优先使用后台直接请求；备用请求和采集子进程沿用 `CREATE_NO_WINDOW` / `SW_HIDE`，本地预览也使用隐藏窗口。

## 状态边界

| 页面状态 | 判断依据 |
| --- | --- |
| 已接入 | 官方报告的财季、发布日期与成功解析记录一致，且有本季实际观测；去年比较列不能证明本季接入。 |
| 已发布 · 待采集 | 官方正文证实已发布，但缺少本季有效解析。图表保留旧值。 |
| 尚未发布 | 官方明确公告未来举行日期且尚未到期；公告发布日期和举行日期分别保存。 |
| 检查失败 · 展示缓存 | 请求失败，但有上次已核验发布记录或实际数据。原获取时间保留。 |
| 检查失败 | 无已核验发布缓存，本次也无法检查。不能解释为未发布。 |
| 发布时间待确认 | 没有可验证的发布日历或正式报告候选；不推测。 |
| 未配置 | 没有该公司的官方发现入口。 |

「最新财报已接入」表示有该财季已核验数据。各指标可能披露不同，页面另列本季已覆盖数量，并展开显示哪些图表仍缺本季观测。来源检查失败与已有财季接入可以同时成立。

## 来源与存储

官方入口在 `scripts/industry_releases.py` 的 `SOURCES` 中配置，覆盖 MSFT、GOOG、AMZN、META、NVDA、DELL、AMD、HPE、ORCL、TSM、MU、ETN、VRT。新增季度跟随实际官方链接，历史模板只用于固定的已发布历史导入。

`release-discovery.json` 记录财季、官方发布日期、URL、首次发现、原始内容版本、获取时间和最近检查。各采集文件保存 `ingestedReleases`；`build-industry.mjs` 将它们与实际观测对照后生成 `financialUpdates`。这些文件及季度修订记录保存在 `data-cache` 分支。

`release-discovery.seed.json` 只用于首次恢复已核验历史发布记录。它包含本地实际抓取的官方历史报告事实，不含全文；恢复时验证域名、财季和时间。后续来源失败显示缓存，不把历史种子或恢复时间算作新成功检查。

Oracle 增加 SEC companyfacts 核心财务备用，CIK 为 `0001341439`：收入、营业现金流、新增独立的现金购置固定资产口径。SEC 原始美元除以 1 亿；累计流量仅按相邻、同财政期初差分。`ORCL.cash_ppe_capex` 与原资本开支、非 GAAP 净现金支出分别保存，不串接；备用指标暂不重复进入推荐评分。部分分部收入仍须原始季度附表。

## 已验证和现有限制

2026-10-02 实际检查中，AMD、Dell、NVIDIA、微软的发布列表可自动发现正式财报；台积电识别到官方 2026-10-15 季度发布安排。HPE、Oracle、三家云厂商的当前报告另有已核验官方历史版本。部分官方 IR 列表及 SEC 在本地或云端返回 403、429 或连接失败，当前状态如实显示。

Oracle 主站当前公告正文只有四舍五入摘要，没有完整精确季度附表，不能用摘要代替精确数据。原官方 PDF 的已核验数值继续保留；新季度若精确附表和 SEC 均无法访问，会显示已发布待采集和错误原因。

未来公告能否当天接入，取决于官方入口可访问、链接可发现及财报结构能通过校验。官网结构更改、缺少季度拆分、口径调整和访问限制均会保留历史并显示待采集，不生成替代数值。

## 验证

新增测试覆盖新季度发现、官方域限制、预告/实报区分、种子缓存、当前季度与比较列、财季与单位、累计 Q4 差分、定向采集、失败恢复、重试退避和隐藏进程。既有计算/研究测试、类型检查与生产构建一起运行；上线后再次检查公开 `industry.json` 的发布状态和观测期。
