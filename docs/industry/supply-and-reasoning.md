## 进入研究结论

采集 → 校验与修订 → 原子缓存 → 行业引擎 → 量化研究 → 页面。当前快照的云平台、数据中心建设、电力设备、服务器与网络、半导体及加速器、晶圆代工、存储和整体8个目标通过正式研究因子门槛。

修复52/53周财季结束日跨月造成的虚假缺期。同公司、同指标族优先选择完整可标准化的直接历史，再比较信号，不因短历史的极端涨幅重复增加权重。引擎版本为 `industry-1.5.0`，因子版本为 `industry-evidence-factor-2.4.0`。规则变更在版本对比中单独说明。

通过因子门槛表示可以形成产业研究分数，不表示交易收益已得到验证。此前建立的模拟跟踪继续积累未来1、3、6个月的实际样本，不回填虚构的历史交易结果。

**仍无法补齐：**先进封装尚缺连续、可比的单项实际收入/订单、盈利与产能历史；宽口径封测收入、扩建计划和机构预测不能冒充这些数据。材料环节仍缺AI相关订单、盈利与成本转嫁证据，商品价格单独不足以评分。这两个目标继续明确显示缺口。

## 自动检查与来源边界

新增适配器 `industry_supply_evidence.py` 进入既有后台每日调度；Equinix从官方季度索引发现实际链接，Arista进入财报发布发现与解析重试链。官方索引被限流或改版时，状态为检查失败或缓存，不能宣称已确认未来所有更新。

每次观测保留实际期末、可核验的官方发布日期、获取时间、原始附件链接、文件哈希及修订版本。来源失败保留上次成功记录；首次失败显示获取失败，未发布或未配置继续保留原状态。网页刷新只读缓存。历史种子有文件与指标白名单、SHA256校验，当前源同期间修订优先；补回旧历史不修改原始发布时间、获取时间和版本，也不覆盖当前缺失值。

Windows子进程保持隐藏运行；新增来源主要使用进程内网络请求，后台检查不要求用户打开网页。

## 推理模型：接入完成，尚未启用

用户尚未开通API，按“先完成接入和测试”交付。已完成后台请求、结构化输出、完整流程模拟测试，**没有进行真实付费模型调用**，因此尚不能验证实际账户权限、接口可达性或模型输出质量。页面显示未配置，并继续提供确定性研究结果。

默认配置为 `gpt-5.4`、中等推理强度。模型可通过后台变量替换；输出包含正面证据、反向证据以及基础/改善/恶化三种条件性情景，每种都说明什么变化会使判断失效。模型引用必须匹配指标ID、观测日期与版本；错误引用、拒绝、非JSON、截断输出均不成为有效结论。机构预测和未来投产计划明确属于情景。

调用记录保存在持久数据分支：配置模型、实际返回模型版本、提示版本、输入哈希、请求ID、状态、耗时、输入/缓存输入/输出/推理token、引用匹配率和估算费用。推理token包含在输出token中，不重复计费。未知计价或缺少用量时费用为空，不能填零；引用匹配率不是投资准确率。页面可展开“推理模型接入与调用记录”。

相同输入复用已验证结果，失败默认等待60分钟重试，每个UTC日默认最多8次调用。账户账单与后台上限分别管理；费用是按返回用量与[官方模型单价](https://developers.openai.com/api/docs/models/gpt-5.4)计算的小计，不代替账单。超长上下文等未覆盖的计价情况保留未知。

## 将来启用

在仓库 Settings → Secrets and variables → Actions 中，将账户创建的项目API密钥保存为后台Secret `OPENAI_API_KEY`；不要放进前端变量或聊天。Variables可以设置：

| 名称 | 默认值 |
| --- | --- |
| REASONING_MODEL | gpt-5.4 |
| REASONING_EFFORT | medium（low/medium/high） |
| REASONING_MAX_OUTPUT_TOKENS | 16000，含推理token |
| REASONING_TIMEOUT_SECONDS | 180 |
| REASONING_MAX_DAILY_CALLS | 8 |
| REASONING_RETRY_MINUTES | 60 |

运行现有“Update data and deploy website”工作流。只有实际返回并通过引用、情景和证据校验后，页面才显示模型已启用；失败则显示真实原因并保留可审计的规则结果。
